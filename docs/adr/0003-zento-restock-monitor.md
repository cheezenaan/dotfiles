# ADR-0003: uniball ZENTO 再入荷監視ツール

## Status

Accepted (2026-08-18)

## Context

uniball ZENTO シグニチャーモデルは流通量が少なく、通販の在庫が復活しても短時間で消える。
在庫が戻った瞬間に通知を受け取りたい。

対象は 2 モデルある。
2025年2月発売の単色モデル（参考価格 3,300円）と、2026年6月25日発売の 3色ボールペン（参考価格 5,500円）で、商品名が「シグニチャー」で重なるため検索結果が混ざる。

販路ごとに取得手段の難易度が違う。

- 楽天市場と Yahoo!ショッピングは公式 API があり、在庫有無をフラグで絞り込める
- 三菱鉛筆公式ストアや文具店はスクレイピングするしかなく、在庫表記がサイトごとに違う
- Amazon は規約でスクレイピングが禁止されており、PA-API には売上実績の要件がある

## Decisions

`tools/zento-watch/` に置き、chezmoi の展開対象から外す（`.chezmoiignore` に `tools/`）。
$HOME に配布する設定ではなくリポジトリローカルの道具であり、実行場所を固定したいため。

標準ライブラリだけの Python 単一スクリプトにする。
macOS 同梱の python3 でそのまま動き、後で launchd に載せるときに依存解決を挟まずに済むため。

在庫判定は「在庫なし → 在庫あり」の遷移だけを通知条件にする。
在庫ありを毎回通知すると、売れ残っている転売品で通知が埋まって本命を見落とすため。
検索結果から消えた出品は在庫なしとして記録し、再出現時に再通知できるようにする。

商品の絞り込みは OR グループの AND 連結（`match.all_of`）で表現する。
「シグニチャー かつ（3色 または 三色）」のような条件が必要で、include_all と include_any の 2 本立てでは書けないため。
突き合わせ前に NFKC 正規化と空白除去をかけ、全角半角と表記揺れを吸収する。

価格上限（`max_price`）で足切りする。
定価の 3 倍を超える転売出品が API の結果に混ざるため。

Amazon は対象に含めない。
規約に反するうえ、代替の Keepa API は有料で、楽天と Yahoo でカバーできる範囲に対して割に合わないため。

HTML ページの在庫判定は、売り切れマーカーを在庫ありマーカーより先に評価する。
カートボタンが無効状態で HTML に残るサイトがあり、ボタンの存在だけでは在庫ありと言えないため。
どちらにも一致しない場合は判定不能として扱い、前回の状態を書き換えない。

まず手動実行のみとし、常駐方式（launchd か GitHub Actions cron）は判定精度を確認してから決める。

## Known Risks

- 楽天と Yahoo の API は 1 クエリ 30 件までしか見ないため、出品が多いと取りこぼす。
  `queries` を絞る運用でカバーする
- 通知クールダウン（既定 6 時間）は、同一出品が短時間で在庫を出し入れした場合に 2 回目を抑制する。
  検索結果の順位変動による誤通知を抑える方を優先した
- JavaScript で在庫を描画するページは HTML 監視では取れない。
  `--probe` で候補が出ないことで気づける
- 実店舗の入荷は検知できない
